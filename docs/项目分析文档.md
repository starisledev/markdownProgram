# 砚屿（Markora）项目分析文档

> 面向阅读者：项目作者 / 新加入的开发者。目标是让你读完就能明白：这是一个什么项目、它怎么跑起来、每个文件在干什么、改哪一行会影响什么。

---

## 1. 这是什么项目

**砚屿**（英文名 Markora）是一款 **Typora 风格的「所见即所得（WYSIWYG）Markdown 编辑器」**，运行在 Windows 桌面。

核心体验一句话：**你输入 Markdown 语法（`#`、`-`、`> `、```` ``` ```` 等），它不显示原始符号，而是直接渲染成排版后的效果**，就像在用 Word 写 Markdown。所有文档都保存在本地，不联网、不上传。

**当前版本：v1.3.0**（已经发布到 GitHub Releases）。

### 主要功能一览

| 功能 | 说明 |
| :--- | :--- |
| 所见即所得编辑 | 输入规则即时转换：标题 / 列表 / 任务清单 / 引用 / 代码块 / 表格 / 分割线 |
| 行内格式 | `**加粗**` `*斜体*` `~~删除线~~` `==高亮==` `` `代码` `` 闭合即生效 |
| 工作区模式 | 打开一个文件夹，左侧文件树浏览并编辑所有 `.md/.markdown/.txt` |
| 查找替换 | 编辑器内高亮查找、单处替换、全部替换 |
| 多主题 | 浅色 / 深色 / 夜间 / 纸感 四套主题，标题栏颜色联动 |
| 多窗口 | `Ctrl+N` 打开独立编辑窗口，各窗口独立的文档 |
| 导出 | Markdown 源码 / 完整 HTML / 通过打印导出 PDF |
| 文档管理 | 最近文档、最近工作区、重命名、删除文档 |
| 附带能力 | 代码高亮、Mermaid 图表渲染、表格、脚注、文档统计、缩放、全屏 |

## 2. 技术栈与架构

```
┌────────────────────────────────────────────────────────────┐
│                       Electron（v34）                       │
│                                                            │
│  ┌───────────────────────┐      ┌───────────────────────┐  │
│  │  主进程 electron/     │      │  渲染进程（页面）       │  │
│  │  main.js              │  IPC │  frontend/ 纯静态前端   │  │
│  │  · 创建窗口           │◄────►│  HTML + CSS + JS      │  │
│  │  · 文件系统读写       │      │  （零构建，浏览器可直接 │  │
│  │  · 打开/保存对话框    │      │   打开预览）            │  │
│  │  · 最近工作区持久化   │      │                        │  │
│  │  · 多窗口/主题联动    │      │  preload.js 注入        │  │
│  └───────────────────────┘      │  window.markoraBridge  │  │
│                                 └───────────────────────┘  │
└────────────────────────────────────────────────────────────┘
```

- **外壳**：Electron（Chromium 负责渲染 UI，Node.js 负责系统能力）。这是它从 Tauri/Rust 迁移过来的原因之一：安装包自带 Chromium，不用依赖系统组件。
- **前端**：原生 HTML/CSS/JS，**没有任何构建步骤、不依赖 npm 打包**。前端文件同时也是纯网页，浏览器打开 `frontend/index.html` 就能预览（只是没有文件对话框等系统能力，会自动降级）。
- **通信**：渲染进程无法直接访问 Node，通过 `preload.js` 注入的 `window.markoraBridge`，用 `ipcRenderer.invoke` 调主进程能力。

> 和 Typora 的技术路线同源（Electron + contenteditable + 自研渲染），只是我们更轻量。

## 4. 程序是怎么启动的

```
双击 Markora.exe
   ↓
main.js: app.whenReady() → 创建窗口（1320×860，最小 780×540，居中）
   ↓
加载 frontend/index.html，并挂载 preload.js
   ↓
页面脚本依次执行：
  highlight.js → markdown.js → to-markdown.js → editor.js → store.js → app.js
   ↓
app.js init() 做了这些事：
  1. 从 localStorage 恢复主题、缩放、上次打开的工作区目录
  2. 初始化编辑器内核（Editor.init）
  3. 打开「上次编辑的文档」（Ctrl+N 新窗口则新建空白文档）
  4. 绑定菜单、快捷键、查找替换、抽屉、拖放等事件
  5. 渲染「最近文档 / 最近工作区」列表
```

关键点：
- **窗口地址带参数**：新窗口加载 `index.html?new=1`，前端据此知道「我是新窗口，直接新建空白文档」。
- **窗口标题**：打开文档后前端调用 `bridge.setWindowTitle()`，主进程把标题栏更新为「文档名 — 砚屿」。

## 5. 前后端通信：window.markoraBridge

前端**永远不直接碰 Node**。所有系统能力都通过 `window.markoraBridge` 调用，底层是 `ipcRenderer.invoke(频道名, 参数)`，主进程 `ipcMain.handle` 响应。

接口对照表（前端调用方法 → 主进程频道 → 作用）：

| 前端方法 | 主进程频道 | 作用 |
| :--- | :--- | :--- |
| `openFolder()` | `open_folder` | 弹系统对话框选文件夹 → 记为最近工作区 |
| `openFileDialog()` | `open_file_dialog` | 弹「打开文件」对话框，返回**路径字符串**（取消返回 null） |
| `recentWorkspaces()` | `recent_workspaces` | 读取最近工作区列表 |
| `listDir(dir)` | `list_dir` | 列举目录（过滤隐藏/跳过 node_modules 等/只显示 md 相关） |
| `readFile(path)` | `read_file` | 安全读文件（≤8MB、类型白名单、剥离 BOM） |
| `writeFile(path, content)` | `write_file` | 安全写文件 |
| `saveFile({filename,content,kind})` | `export_file` | 弹「另存为」对话框导出 |
| `mdToHtml(md, title)` | （前端本地实现） | Markdown → 完整 HTML 文档（`window.MD.render` 直接渲染） |
| `newWindow(mode)` | `new_window` | 新建独立编辑窗口 |
| `applyTheme(mode)` | `apply_window_theme` | 标题栏配色跟随主题 |
| `setWindowTitle(title)` | `set-window-title` | 设置原生窗口标题 |
| `quit()` | `quit_app` | 退出应用 |
| `onMenu(cb)` | （保留占位） | 菜单是前端 HTML 实现的，此接口不会触发 |

> 迁移历史：这套接口形状和原来 Tauri 版（`tauri-bridge.js` → Rust）**完全一致**，所以从 Rust 换到 Electron，前端 `app.js` 几乎不用改。

## 6. 前端核心模块详解

### 6.1 editor.js —— 编辑内核（最重要的文件）

它把一个 `contenteditable` 的 `<div>` 变成 Typora 式编辑器。核心机制：

**输入即转换（规则驱动）**
- **块级规则**（`applyBlockRules`）：在段落开头输入 `# 标题 `、`> `、`- `、`1. `、`[] `、````` ```js ````、`---`，输入到空格/换行时立刻把整个块转换成对应元素（`<h1>`、`<blockquote>`、`<ul>`、`<pre>`…）。
- **行内规则**（`applyInlineRules`）：输入 `**加粗**` 这类闭合标记时，把标记部分换成 `<strong>` 等元素，光标自动跳到闭合符后面。

**回车 / 退格逻辑（今年修复的重点）**
- 回车 = 智能切分：在段落中间回车 → 拆成两段；在列表里回车 → 新列表项；空列表项回车 → 退出列表；引用内回车 → 内部新段落。
- 退格 = 智能合并：段首退格 → 并入上一块；列表项开头退格 → 反缩进/转段落。
- **两个关键修复**：① 空段落回车不再把 `<br>`「抽走」（否则连续回车永远停在同一行）；② 处理全过程有 try/catch 兜底自愈，任何异常都不会把回车/退格键「弄死」。

**选区保护**：记录编辑区内最后一次选区；弹窗/文件树夺走焦点后，格式命令仍作用于原文档。

对外暴露的 API：`Editor.setMarkdown/getMarkdown/setBlockType/wrapSelection/insertTable/insertCodeBlock/...`

### 6.2 markdown.js —— Markdown 渲染器（零依赖）

`MD.render(源码) → HTML 字符串`。支持：标题 / 引用 / 嵌套列表 / 任务清单 / GFM 表格 / 围栏代码 / 分割线 / 行内代码 / 加粗斜体删除线高亮 / 链接图片 / 脚注 / 自动链接 / HTML 透传。

注意：它只负责 **加载文档时把源码变成 DOM**，以及粘贴/拖入时把 Markdown 文本转成 DOM；编辑过程中**不重新渲染整篇**（这是流畅的关键）。

### 6.3 to-markdown.js —— 反向序列化器

`MD2.toMarkdown(editorDOM) → Markdown 源码`。把编辑器里的 DOM（`h1`、`strong`、`table`、`ul`…）还原成原始语法，并且**保留标记符号**（`**`、`~~`、`==`、`` ` ``）；遇到行首是块标记的内容会转义，防止导出后再导入时被误渲染。用途：保存文档、`Ctrl+S` 导出、复制源码、文档统计。

### 6.4 highlight.js —— 轻量代码高亮

预设 20+ 种语言（JS/TS/Python/Java/C/Rust/SQL/HTML/CSS…）的正则规则，把代码里的关键字、字符串、注释等包上 `.tok-*` 类，由 CSS 上色。

### 6.5 store.js —— 数据层

所有文档存在 **localStorage**（键 `markora.workspace.v1`），结构：

```
{
  version: 1,
  files: { 文档id: { id, name, type, parent, content, path, fsPath, created, modified } },
  settings: { theme, zoom, openId, workspaceDir, ... },
  order: [文档id按顺序]   ← 决定「最近文档」排序依据
}
```

- 首次启动自动播种 2 个示例文档（欢迎 + 语法一览）。
- 所有写入走 300ms 防抖，避免频繁序列化。
- 工作区里的磁盘文件是**双写**：内存/本地库一份 + 实时写回磁盘原文件（`fsPath` 指向磁盘路径）。

### 6.6 app.js —— 应用层（胶水层）

把所有模块串起来：

- **HTML 菜单栏 + 格式工具栏**：文件/编辑/视图/格式/帮助全是前端 DOM + 事件；「视图 → 格式工具栏」可展开一行快捷格式按钮（加粗、标题、列表、链接、表格等），选中状态自动高亮，与底部状态栏的光标行/列联动。
- **工作区（文件树）**：打开文件夹 → 左侧抽屉显示目录树（懒加载子目录）；点击 `.md` 用 `read_file` 读入并以「磁盘文件」身份打开（保存直接写回原文件）。
- **查找替换**：在 DOM 里定位命中文本，用高亮 `<span>` 包裹，支持上一个/下一个/单处替换/全部替换。
- **主题**：切换 `<html data-theme="…">`，CSS 变量全站换肤；状态持久化到 settings。
- **首帧无闪烁**：`index.html` 顶部有一段内联脚本，在样式加载前就从 localStorage 读出主题设置 `<html>` 的 `data-theme`。
- **导出**：Markdown（调 `saveFile` 弹另存为）/ HTML（`MD.render` 生成完整带样式的网页）/ PDF（`window.print()` 打印，页面对 `@media print` 做了专门样式）。
- **多窗口**：`Ctrl+N` 调 `newWindow()`，主进程开新窗口加载 `?new=1`。
- 其他：文档统计弹窗、快捷键速查、关于、缩放（改编辑器字号）、全屏、Toast 提示、拖入文件。

## 7. 三个最关键的运行流程（看懂这三个就懂了八成）

### 流程 A：打开一个磁盘文件

```
菜单「文件 → 打开 Markdown…」→ 原生对话框选文件
   ↓ bridge.openFileDialog() → 拿到绝对路径（字符串）
   ↓ bridge.readFile(路径) → { content, mtime }（校验扩展名/大小、剥离 BOM）
   ↓ openFsFile()：
       · 在本地库中查找有没有已打开过这个文件（按 fsPath）
       · 有则复用并刷新内容，没有则新建一条记录（fsPath=磁盘路径）
       · Editor.setMarkdown(content) 渲染进编辑器
       · 窗口标题 = 「文件名 — 砚屿」
保存时：内容变了 → 本地库更新 + bridge.writeFile(写回磁盘)
```

### 流程 B：输入 `## 我的标题`

```
用户敲下: '#' '#' ' ' '我' '的' '标' '题'
每次按键触发 input 事件 → applyBlockRules()
当段落文本匹配 ^#{1,6}[ \t]+ 时：
  把整个 <p> 替换成 <h2>，光标放到标题文字末尾
  编辑器 DOM 变成 <h2>我的标题</h2>
（行内格式同理：敲出 **加粗** 时把 ** ** 替换成 <strong>）
```

### 流程 C：保存

- **自动保存**：内容变化后 600ms 防抖，把编辑器 DOM 序列化成 Markdown 存入本地库；若是磁盘文件再写回磁盘。另有每 30 秒的兜底自动保存。
- **手动保存**：`Ctrl+S` —— 磁盘文件直接写盘并提示「已保存到磁盘 ✓」；普通文档则是弹「另存为」导出。
- **关闭窗口**：`beforeunload` 里再保存一次，防止丢最近的编辑。

## 8. 构建、打包、发布

### 本地开发

```bash
npm install      # 首次安装依赖（electron ^34 + electron-builder）
npm start        # 启动开发窗口（等同开机运行的效果）
```

### 打包安装包

```bash
npm run dist     # 产出 NSIS 安装包 + 便携 zip 到 dist-electron/
```

配置在 `package.json` 的 `build` 字段（appId、图标、NSIS 选项、产物命名）。

### 发布 GitHub Release

```bash
bash dist/publish_release.sh
```

脚本会自动：从 Windows 凭据管理器读取 GitHub token → 创建 v1.3.0 Release → 上传安装包 / 便携包 / README → 删除旧的 v1.2.0/v1.1.0 Release。

> 注意这台机器的两个环境特性：
> 1. GitHub 下载慢/超时 → 打包时给进程设 `HTTPS_PROXY=http://127.0.0.1:7897`（Clash 端口）。组件已缓存，一般不再需要。
> 2. fine-grained token **无法单独删除某个 Release 资产**；脚本采用「删整个 Release → 同 tag 重建」方式完成替换。

## 10. 常见问题 / 注意事项

1. **`contenteditable` 的坑**：浏览器对可编辑 DOM 的默认行为（Delete 键跨块合并等）与我们的规则偶有冲突，所以回车/退格等键全部由 JS 接管,并带异常兜底。遇到奇怪行为先检查是否是浏览器默认行为介入。
2. **前端零构建是把双刃剑**：浏览器打开 `frontend/index.html` 能直接预览（没 Node 能力），这是设计好的降级路径，别把前端代码改成依赖 `node` 全局。
3. **localStorage 存文档**：文档体积大了会触发序列化开销；这是后续可优化点（如阈值后改 IndexedDB）。
4. **多窗口共享 localStorage**：新窗口能读写同一份本地库，但每个窗口的「当前打开文档」状态是独立的。
5. **`src-tauri/` 空目录**（本机残留）：已无文件，可手动删除。
